## Задание 2: Code review сгенерированного кода.
### Промпт 1
**Промпт:** "Проведи первичный осмотр кода веб-приложения маркетплейса (FastAPI + Pydantic + PostgreSQL, параметры: сервер 127.0.0.1, порт 5432, пользователь mp_user, пароль 12345, база marketplace_platform). Найди подозрительные места, связанные с безопасностью и грубыми нарушениями (например, учётные данные в коде, отсутствие авторизации на важных эндпоинтах). Верни краткий список потенциальных проблем без детального описания — только заголовки."
**Результат:** Составлен краткий список подозрительных мест и нарушений безопасности:
    ---
     1. Отсутствует модуль `app/logger.py` — импортируется в 7 файлах, но
        физически не существует. Приложение не запустится.
     2. Нет аутентификации на всех CRUD-эндпоинтах — 5 роутеров (products,
        sellers, orders, reviews, commissions), ~20 эндпоинтов без
        Depends(get_current_user). Любой может создавать, читать, изменять и
        удалять любые данные.
     3. JWT-секрет жёстко закодирован — app/auth/config.py:
        "super-secret-key-change-in-production-2026". Подделка токенов без знания
         пароля.
     4. Пароль БД зашит в коде — app/config.py: "12345" для пользователя mp_user.
     5. CORS `allow_origins=["*"]` — любой внешний сайт может отправлять запросы
        к API.
     6. Нет rate limiting на `/login` и `/register` — неограниченный brute-force
        подбора пароля и спам-регистрации.
     7. Нет эндпоинта смены пароля — пользователь не может сменить пароль ни
        через API, ни через профиль.
     8. JWT живёт 24 часа — jwt_expire_minutes = 1440. Избыточно длинное окно для
         перехваченного токена.
     9. Mass Assignment в `update_profile()` — setattr(user, field, value) без
        белого списка полей. Будущее добавление поля role в UserUpdate приведёт к
         escalation.
     10. Нет проверки ownership в CRUD-сервисах — даже после добавления
         get_current_user любой пользователь сможет изменить/удалить чужие товары,
          заказы и отзывы.
     11. Поле `buyer_name` не привязано к `current_user` — любой может создать
         заказ/отзыв от чужого имени (просто указав строку в body).
     12. Timing oracle на `/login` — проверка существования пользователя
         происходит до bcrypt; разница во времени ответа позволяет перебором
         определить, зарегистрирован ли email/username.
