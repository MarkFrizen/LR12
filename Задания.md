Вариант 15.
Предметная область: платформа маркетплейса
Описание области: продавцы, товары, заказы, отзывы, комиссии

Задание 1. Создание полноценного веб-приложения 
Используя ИИ для 80% кода, создать полноценное веб-приложение для предметной области. Функционал: аутентификация (регистрация/логин/JWT), работа с основной 
сущностью (CRUD), дополнительные сущности (не менее 3 связанных), отчёты/аналитика, админ-панель (или права доступа). Задокументировать все используемые промпты и их результаты. Итоговый код должен быть полностью рабочим и протестированным. 

Задание 2. Code review сгенерированного кода.
Провести критический анализ кода, сгенерированного ИИ в рамках курсовой работы предыдущих заданий. 
Найти и испраывить не менее 5 ошибок/неоптимальностей (логические ошибки, уязвимости, проблемы производительности, нарушения стиля, отсутствие обработки исключений). Написать отчет в формате: "Что сгенерировал ИИ -> В чем проблема -> Как исправил"

Задание 3. Настройка локальной LLM 
(задание опционально)
Развернуть локальную LLM на своём компьютере (через Ollama: CodeLlama, Qwen Coder или Mistral). Настроить автодополнение кода в VS Code (через Continue.dev или аналоги). Сравнить качество подсказок локальной модели vs облачного решения (Copilot/Cursor) при решении 3 типовых задач из предметной области. Результат — 
таблица сравнения (точность, скорость, релевантность). 

Задание 4. Интеграция ИИ в CI/CD 
Настроить GitHub Actions workflow, который: 
• Запускается при создании Pull Request. 
• Автоматически описывает изменения с помощью ИИ (используя OpenAI API или локальную модель). 
• Публикует этот комментарий в PR. 
• (Дополнительно) Запускает автоматическое ревью кода с поиском типовых проблем. 
Результат — рабочий workflow и скриншот комментария от ИИ в PR. 

Задание 5. Создание плагина для IDE 
(задание опциоанльно)
Создать простой плагин/расширение для VS Code (или другого редактора), который: 
• По горячей клавише отправляет выделенный фрагмент кода в ИИ с запросом: «Объясни этот код». 
• Получает ответ и выводит его в отдельной панели/тултипе. 
• (Дополнительно) Добавить возможность задать кастомный промпт. 
Результат — код плагина, инструкция по установке, демонстрация работы. 

Задание 6. Сравнение разных ИИ-моделей
(задание опционально) 
Выбрать одну сложную задачу из предметной области (например, «написать функцию расчёта оптимального маршрута доставки» или «реализовать алгоритм ранжирования товаров»). Попросить решить её минимум 3 разные модели: GPT-4, Claude, Gemini (или локальные: CodeLlama, Qwen-Coder). Сравнить качество решения по критериям: корректность, полнота, безопасность, читаемость кода, количество итераций для уточнения. Результат — сравнительный анализ в виде таблицы и выводы. 

Задание 7. Генерация unit-тестов с высоким покрытием 
Разработать систему промптов для автоматической генерации тестов с покрытием не менее 90%. Промпты должны учитывать: граничные случаи предметной области 
(минимальные/максимальные значения, пустые списки, отрицательные цены и т.д.),обработку ошибок, асинхронный код. Протестировать на реальном коде из Задания 1. Зафиксировать промпты, сгенерированные тесты и итоговое покрытие (отчёт coverage.py). 

Задание 8. Исправление галлюцинаций ИИ 
(задание опционально) 
Найти в сгенерированном коде (или специально спровоцировать) ситуацию, когда ИИ «галлюцинировал»: предложил несуществующую функцию/библиотеку/метод, выдумал API, использовал неправильные типы данных, нарушил логику предметной области. Самостоятельно исправить ошибку. Написать эссе-рассуждение: «Почему ИИ ошибся, как распознать галлюцинацию, как изменить промпт, чтобы избежать подобного в будущем».
